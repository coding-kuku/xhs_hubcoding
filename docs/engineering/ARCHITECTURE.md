# 工程架构

## 运行边界

最终小游戏是纯 HTML、CSS 和原生 JavaScript 项目，根目录 `index.html` 是唯一入口。运行时不依赖 Node、服务器、构建工具或网络。

Node 仅用于仓库内的离线测试和概率模拟，不进入小红书上传包。

## 分层

| 层 | 职责 | 目录 |
|---|---|---|
| 界面层 | 页面、触摸事件、动画、可访问性 | 根目录，后续 `src/ui/` |
| 游戏规则层 | 状态迁移、拍卖、处置、仓库、跨日 | `src/core/game-engine.js` |
| 内容生成层 | 每日五柜、线索、市场、商户、NPC | `src/core/daily-generator.js` |
| 数据层 | 经济和线索基线 | `src/data/` |
| 验证层 | 单元测试、压力测试、经济模拟 | `tests/`、`tools/` |
| 决策层 | 产品和机制的可读文档 | `docs/` |

## 数据原则

- 每日内容由“本地日期 + 存档种子 + 首次进入时资产档”确定。
- 生成后保存完整日数据；同日重进只恢复，不能重抽。
- 界面只接收公开视图，真实物品和 NPC 私有估价不能提前泄露。
- `localStorage` 存档需要版本字段和迁移策略；坏档时允许安全开新局。
- 随机数必须可复现，测试不能依赖不可控的 `Math.random()`。

## 当前技术债务

经济数值同时存在于 `src/data/economy-config.json` 和 `src/core/daily-generator.js` 的常量中。下一步整合应创建普通本地 JS 数据文件，例如 `src/data/economy-data.js`，由 `<script src>` 提前加载并成为唯一运行时数据源。

不能在浏览器中用 `fetch` 读取 JSON，因为项目要求完全离线且明确禁止网络请求。JSON 目前只服务开发期模拟和可读配置。

## 发布包与仓库的区别

仓库包含文档、测试、报告和历史原型；发布包只包含运行所需文件。发布时必须使用明确白名单，不把整个仓库直接压缩。
